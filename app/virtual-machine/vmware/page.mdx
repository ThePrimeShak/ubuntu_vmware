# Virtual Machines and VMware

## What is a virtual machine?

A **virtual machine (VM)** is an isolated software environment that behaves like a computer. A VM has virtual CPUs, memory, storage, network adapters, and other devices supplied by a **hypervisor**. The operating system running inside the VM is the **guest**; the physical computer is the **host**.

Virtual machines are especially useful in an operating-systems lab because a mistake inside the guest is less likely to damage the host. This isolation is useful, but it is not an absolute security boundary: keep VMware and the guest operating system updated and avoid running untrusted malware.

## Hypervisor types

### Type 1: bare-metal

A type-1 hypervisor runs directly on the hardware and is common in servers and data centres. Examples include VMware ESXi and Microsoft Hyper-V.

### Type 2: hosted

A hosted hypervisor runs as an application on a desktop operating system. VMware Workstation and Oracle VirtualBox are familiar examples. Modern implementations can also use hardware-virtualisation services provided by the host OS, so the boundary between the two categories is not always perfectly simple.

## Why use a VM in this lab?

- Keep the host operating system and its partitions unchanged.
- Reset experiments by reverting a snapshot or recreating the VM.
- Run Linux and the host OS at the same time.
- Practise installation, users, packages, services, and networking safely.
- Use a repeatable hardware configuration across different student computers.

The trade-offs are additional RAM, CPU, and storage usage. Graphics-intensive workloads and direct hardware access may also perform better on a physical installation.

## VMware Workstation

**VMware Workstation Pro** is a desktop hypervisor for Windows and Linux hosts. VMware Fusion is the related product for macOS. Workstation supports common lab features such as snapshots, virtual networks, shared folders, clipboard integration, and adjustable virtual hardware.

Since Workstation Pro 17.5.2, Broadcom makes the current desktop hypervisor available without a licence key for personal, educational, and commercial use. Downloads require a Broadcom Support Portal account, and availability can be subject to regional export requirements.

## Recommended lab configuration

| Resource  | Suggested value                   | Notes                                                                     |
| --------- | --------------------------------- | ------------------------------------------------------------------------- |
| CPU       | 2 virtual cores                   | Do not assign every host core to the VM                                   |
| Memory    | 6 GB for Ubuntu Desktop 26.04 LTS | Leave enough memory for the host OS; Debian's needs depend on the desktop |
| Storage   | 30–40 GB, dynamically allocated   | Ubuntu documents at least 25 GB of free storage                           |
| Network   | NAT                               | Easiest internet access for most labs                                     |
| Firmware  | UEFI                              | Suitable for current Ubuntu and Debian releases                           |
| Snapshots | One clean snapshot after setup    | Snapshots are not backups                                                 |

> On an 8 GB host, a 6 GB Ubuntu Desktop VM leaves little memory for the host. Consider a minimal Debian VM or a lighter desktop instead. Never allocate more resources than the host can sustain.
