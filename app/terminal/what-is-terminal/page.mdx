# Terminal, Shell, and Command Line

These terms are related but not identical:

- A **terminal emulator** is the graphical or text application that displays a command-line session, such as GNOME Console, GNOME Terminal, Konsole, or Windows Terminal.
- A **shell** is the program that reads commands and starts other programs. Bash is the common default on Ubuntu and Debian; Zsh and Fish are alternatives.
- The **command-line interface (CLI)** is the text-based interaction style used inside the terminal.

## Why the terminal matters

- The same commands can work locally, over SSH, and in automated scripts.
- Text commands are easy to document and repeat.
- Servers often run without a desktop environment.
- Logs, permissions, processes, services, and package tools expose rich command-line interfaces.

A terminal is powerful, but it is not inherently superior to a graphical interface. Use the interface that makes the task safe, clear, and repeatable.

## The prompt

A typical Bash prompt may look like:

```text
student@ubuntu-lab:~/projects$
```

It shows the current user, host, working directory, and a `$` marker for a regular user. A root shell often uses `#`; this is a warning that commands have elevated privileges.

## How a command is interpreted

In this example:

```bash
ls -lah /var/log
```

- `ls` is the command.
- `-lah` combines options that change its behaviour.
- `/var/log` is the path argument.

Quoting, redirection, pipelines, and wildcard expansion are performed by the shell. For example, `>` replaces a file's content while `>>` appends, so redirection deserves the same care as file-deletion commands.
