# Dual Boot with Linux

In a **dual-boot** setup, two operating systems are installed on physical storage and a boot menu selects one at startup. Unlike a VM, only one of the installed systems normally runs at a time and it uses the hardware directly.

This page explains the concept; it is not a substitute for a device-specific installation plan.

## Before changing partitions

1. Create a verified backup on another device.
2. Make a Windows recovery drive and save the BitLocker recovery key, if applicable.
3. Check whether the computer boots in UEFI mode and uses GPT partitioning.
4. Disable Windows Fast Startup before sharing NTFS data with Linux.
5. Follow the [Ubuntu BitLocker guidance](https://ubuntu.com/desktop/docs/en/latest/reference/bitlocker-during-ubuntu-installation/) before installing alongside encrypted Windows. Suspending BitLocker does not decrypt the volume; the guided installer may require turning it off and waiting for decryption. Check recovery and re-encryption options before changing it, especially on a managed computer.
6. Use Windows Disk Management to shrink the Windows partition and leave unallocated space for Linux.

## Current UEFI/GPT layout

Most current PCs use GPT and an **EFI System Partition (ESP)**. The ESP is usually FAT32, not NTFS, and both operating systems can place boot files in it. GPT does not impose the old four-primary-partition limit.

An illustrative layout might be:

| Partition                              | Typical format              | Purpose                                                                                 |
| -------------------------------------- | --------------------------- | --------------------------------------------------------------------------------------- |
| EFI System Partition                   | FAT32                       | Existing UEFI boot files; mount at `/boot/efi`, do not format during Linux installation |
| Microsoft reserved/recovery partitions | Microsoft-defined           | Keep unchanged                                                                          |
| Windows system volume                  | NTFS                        | Windows and its applications                                                            |
| Linux root `/`                         | ext4                        | Linux system and, in a simple layout, user files                                        |
| Linux swap                             | Swap partition or swap file | Optional based on the chosen setup                                                      |

Device names and sizes vary. NVMe storage commonly appears as `/dev/nvme0n1p1` rather than `/dev/sda1`.

## Installer choices

When available, **Install alongside Windows** is the simplest automated option. Manual partitioning gives more control but also makes it easier to select or format the wrong partition.

Install Windows first when building a new dual-boot computer, then Linux. Linux installers normally detect Windows and configure GRUB or another boot manager. Firmware updates and Windows updates can still change boot order, so keep recovery media available.

## Dual boot or virtual machine?

| Choose a VM when…                      | Choose dual boot when…                                    |
| -------------------------------------- | --------------------------------------------------------- |
| You are learning or experimenting      | You need near-native CPU/GPU or direct hardware access    |
| You want both systems running together | The workload does not perform well in a VM                |
| You want easy snapshots and deletion   | You are comfortable managing partitions and boot recovery |

For this operating-systems lab, a VM is the recommended default because it is easier to reproduce and recover.
