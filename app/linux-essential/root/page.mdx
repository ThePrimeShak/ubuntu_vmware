# Root in Linux

The word **root** has two important meanings: the all-powerful administrator account and the top directory of the filesystem. They are related by name, not by function.

## The root user

The root user has user ID `0` and can read or modify almost every part of the system. This access is necessary for tasks such as installing packages, changing system configuration, managing users, and controlling services.

Ubuntu normally disables direct password login for root. An authorised regular user runs a specific administrative command through `sudo`:

```bash
sudo apt update
```

`sudo` normally asks for the current user's password, records the command, and grants privileges for a limited time. Use `sudo -i` only when a temporary root shell is genuinely necessary, and exit it promptly.

## Safe privilege habits

- Read a command and resolve its paths before adding `sudo`.
- Use the smallest privilege and narrowest target that completes the task.
- Avoid copying commands from untrusted sources.
- Prefer package-manager and service-management tools over manual file deletion.
- Keep a regular user session for everyday work.

> A command such as `sudo rm -rf` can remove system or personal data without an undo operation. It is deliberately omitted from the examples in this guide.

## The root directory

The root directory, written `/`, is the top of the filesystem hierarchy. It is different from `/root`, which is the root user's home directory.

| Path               | Purpose                                                     |
| ------------------ | ----------------------------------------------------------- |
| `/home`            | Home directories for regular users                          |
| `/root`            | Home directory for the root user                            |
| `/etc`             | System-wide configuration                                   |
| `/var`             | Variable data such as logs, caches, and queues              |
| `/tmp`             | Temporary files; retention is not guaranteed                |
| `/usr`             | Most user-space programs, libraries, and shared data        |
| `/boot`            | Kernel, bootloader, and related boot files                  |
| `/dev`             | Device nodes exposed by the kernel                          |
| `/proc` and `/sys` | Virtual filesystems exposing process and kernel information |

On many current distributions, `/bin`, `/sbin`, and `/lib` are symbolic links into `/usr`. Older diagrams that describe them as completely separate locations may not match a current installation.

## Useful administrative commands

| Command                         | Purpose                                                            |
| ------------------------------- | ------------------------------------------------------------------ |
| `sudo apt update`               | Refresh APT package metadata                                       |
| `sudo apt full-upgrade`         | Apply available upgrades, including dependency changes             |
| `sudo adduser student`          | Create a user using Debian/Ubuntu's interactive helper             |
| `sudo usermod -aG sudo student` | Add a user to the `sudo` group without replacing other memberships |
| `sudo systemctl restart ssh`    | Restart the SSH service if it is installed                         |
| `sudo journalctl -u ssh`        | Inspect logs for the SSH service                                   |
| `sudo chown user:group path`    | Change ownership of a known path                                   |

Always replace example users, services, and paths with verified values from your own system.
