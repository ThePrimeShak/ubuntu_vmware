# Linux Basics

## What Linux actually is

Strictly speaking, **Linux is a kernel**: the core software that manages a computer's CPU, memory, devices, processes, and system calls. A complete operating system combines the Linux kernel with user-space tools, libraries, a package manager, and—on desktop systems—a graphical environment.

People often use “Linux” as convenient shorthand for a complete **Linux distribution**, such as Ubuntu, Debian, Fedora, or Arch Linux.

## A short history

- The GNU Project began developing free Unix-like tools in 1983.
- Linus Torvalds released the first Linux kernel in 1991.
- Distributions combined the kernel, GNU tools, package repositories, and installers into complete systems.
- Today, Linux is widely used on servers, cloud platforms, supercomputers, embedded devices, developer workstations, and Android-based devices.

## Linux and Windows: a balanced comparison

| Area                  | Linux distributions                                                          | Windows                                                                    |
| --------------------- | ---------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Licensing             | Mostly free and open source; licences vary by component                      | Proprietary, with open-source components                                   |
| Software installation | Distribution repositories and package managers                               | Microsoft Store, package managers, and installers                          |
| Customisation         | Extensive, including desktop and low-level system choices                    | Broad user customisation with a more standardised core                     |
| Command line          | Shells and command-line tools are central to administration                  | PowerShell, Command Prompt, WSL, and graphical tools                       |
| Typical strengths     | Servers, cloud, development, embedded systems                                | Desktop applications, gaming, enterprise desktops                          |
| Security              | Strong permission model; security still depends on configuration and updates | Strong modern security features; also depends on configuration and updates |

Neither system is automatically secure, fast, or appropriate for every workload. Hardware, software requirements, maintenance, and configuration matter more than simple platform labels.

## What is a distribution?

A **distribution** packages the Linux kernel with system tools, a package manager, repositories, defaults, and release policies. Desktop distributions usually add a graphical environment and common applications.

| Distribution | Good fit for                             | Important characteristic                                         |
| ------------ | ---------------------------------------- | ---------------------------------------------------------------- |
| Ubuntu       | Beginners, education, desktops, cloud    | Predictable LTS releases and extensive documentation             |
| Debian       | Stable desktops and servers              | Community governed and deliberately conservative stable releases |
| Fedora       | Developers and newer Linux technologies  | Closely connected to the Red Hat ecosystem                       |
| Arch Linux   | Experienced users who want control       | Rolling release with a manual, do-it-yourself approach           |
| Linux Mint   | Desktop users moving from Windows        | Familiar desktop experience based on Ubuntu or Debian            |
| Kali Linux   | Authorised security testing and training | Specialised toolset; not intended as a general beginner desktop  |

> For this lab, Ubuntu is the easiest starting point. Debian is included as a second option for students who want to see a more traditional installer and fewer distribution-specific conveniences.

## Core concepts to remember

- Linux is the kernel; a distribution is the usable operating-system package around it.
- Package managers track dependencies. On Ubuntu and Debian, APT verifies signed repository metadata and package checksums; it does not check a separate signature on every installed package.
- Users normally work without administrator privileges and use `sudo` only when required.
- Paths begin at the root directory `/`, and names are case-sensitive.
- The same fundamentals apply across most distributions even when their installers and desktop environments differ.
